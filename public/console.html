Risk indicated

Checkout can be sent twice

POST /api/checkout went out without an Idempotency-Key header. If a customer double-clicks or the browser retries, your server can’t tell the two apart.

Bug capsules

PREVIEW

When something breaks in a test environment, a capsule keeps the last moments before the error. AirlockQA turns it into a Playwright test that reproduces the bug.

Prototype — keep real customer data out. Emails, card numbers, tokens and obvious secrets are scrubbed on a best-effort basis, but capsules aren’t encrypted and storage can still hold sensitive values. Use staging or preview data only.

Captured · 3

How a capsule is made
  1. Your test app keeps a small rolling log of recent clicks, inputs, requests and console messages.
  2. When an error isn’t caught, it saves that log as a capsule with a checksum.
  3. Teleport replays the steps in a fresh browser and writes a repro test.

Connect your pipeline

Run AirlockQA on every push and pull request, and get the result — with its signed receipt — right on the pull request.

Cloud API reachable · api.qbrin.cloud

1 · Where should tests run?

2 · Install

$ 
bun add --dev airlockqa
$ bunx airlock test --cloud

3 · Store the key as a CI secret

Secret nameAIRLOCK_API_KEYGitHub → Settings → Secrets → Actions
  • The CLI sends the key only as an HTTPS Bearer token — never in the run body or a command argument.
  • Don’t expose the secret to workflows triggered by pull requests from forks.
  • Real app secrets stay in your runner; only stand-in values travel to the cloud.

4 · Add the workflow

.github/workflows/airlockqa.yml

name: AirlockQA
on: [push, pull_request]
jobs:
  browser-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: oven-sh/setup-bun@v2
      - run: bun install && bunx playwright install --with-deps chromium
      - run: bunx airlock test --cloud
        env:
          AIRLOCK_API_KEY: ${{ secrets.AIRLOCK_API_KEY }}
      - run: bunx airlock audit
